# 04 码道在项目开发中的应用总结

## 1. 使用方式

码道（CodeArts）贯穿“审计 → 合并 → 实现 → 排障 → 验收”全过程，主要承担：

- **仓库审计与合并**：比对三个演示分支（PDF→MD、模板→教案、PPT 原生制作），梳理可复用模块、
  外部运行时依赖与不可伪造的进度语义，确定“保留 PPT 原生制作、其余重写衔接”的方案。
- **功能实现**：五阶段解析动画、Markdown 渲染与在线编辑、DOCX 渲染预览、教案过程态、
  单页修改加载态、账号密码登录与按用户隔离、自定义模型管理。
- **缺陷定位**：从日志与产物反推根因，而不是猜。例如视觉模型把 JSON 对象写散导致
  `'str' object has no attribute 'get'`；81 页模板目录 600 KB 触发网关 HTTP 400；
  页码字号被当成标题基准导致标题槽全被过滤；模型编辑母版继承对象被导出器拒绝；
  渐变 `url(#id)` 在往返材质化时丢失；模板混排导致首页色调与其余页割裂。
- **质量闭环**：每次修改都跑 `pytest`、导出真实 PPTX、看逐页 PNG、再跑评审；不通过就继续定位，
  不以“看起来没问题”收尾。

## 2. 典型协作片段

| 场景 | 码道的动作 | 人的判断 |
|---|---|---|
| 合并三套演示 | 先读代码与文档，列依赖/契约/风险，再分阶段替换 | 确认“不伪造进度、保留原生制作”的底线 |
| 教案版式不符 | 定位到九段式渲染与图片校验，补“每学时≥2图” | 提供学校模板与验收标准 |
| PPT 制作失败 | 逐层排查视觉缓存、布局请求、标题槽、母版编辑、语义形状、渐变、色调聚类 | 决定修复优先级与可接受的质量边界 |
| 登录与模型 | 设计账号密码 + 数据根隔离 + 模型配置存储，补测试 | 明确“先账号密码、不做邮箱”的产品取舍 |

## 3. 有效的做法

1. **先证据后结论**：读日志、产物 JSON、真实导出文件，再改代码；避免“猜一个补丁”。
2. **小步提交**：每个根因一个提交，提交信息写清现象、根因、修复与验证。
3. **测试兜底**：为每个回归点补用例（视觉批次结构、色调聚类、账号隔离、模型密钥不回传），
   当前 98 passed / 1 skipped。
4. **真实链路验收**：不只看单测，要求真实生成、逐页预览、下载、重启恢复。
5. **把限制写进文档**：Windows/PowerPoint 约束、AGPL 组件、模型网关可达性，提前暴露而不是上线后踩坑。

## 4. 局限与反思

- 模型输出具有随机性，同一提示可能多次才通过容量/语义校验；需要确定性的兜底（结构校验、自动缩放、
  版面聚类）而不只是“再试一次”。
- 码道能快速定位与实现，但**产品取舍、验收标准、许可证与部署环境**必须由人确认。
- 外部运行时（PPT Master）与桌面 Office 是硬约束，不能靠提示词绕过；文档必须如实说明。
- 后续可改进：把“真实 PowerPoint 文字边界”沉淀为可回归的基准集；为模型配置增加连通性巡检；
  在 CI 中固定跑 `pytest` 与关键导出用例。

## 5. 结论

码道在本项目中主要价值不是“写更多代码”，而是**把复杂链路的证据串起来**：从失败现象追到根因，
用测试和真实产物证明修复有效，并把不可逾越的约束如实交付给使用者。
