# 问题与解决方案

1. 浏览器无法访问沙箱内启动服务：进程内接口通过而主机浏览器超时。通过平台审批在主机边界启动本机7863服务，未改旧服务或网络安全设置。
2. 迁移后的阅读参考缺失：旧实现从隐式runs/studio路径找已确认成品。改为显式登记独立PNG与完整内容指纹，只有模板SHA、标题、事实、原图SHA、教师备注和目的匹配才提供阅读参考，绝不作为新预览或成品。
3. Markdown空字段吞掉下一行教师备注：旧正则使用跨行 `\s*`。新增失败测试后改为不跨CR/LF的水平空白匹配，保留中文全角空白兼容。已确认大纲工作流直接保留标准化源文件，不经过不必要的重序列化。
4. 模型字号错误未进入局部修复：旧分支只识别带Object与LAYOUT错误。现在从真实错误的slot编号定位原文字槽，交API定点修复；仍保留90%-105%约束，不程序缩字。
5. 排队取消后恢复可能执行旧队列项：任务操作增加唯一operationId，持锁核验当前queued状态与token后才认领，旧操作不能再次执行。
6. 浏览器自动选文件：Edge扩展未开放file URL访问，选择器setFiles被拒绝。未改扩展权限；HTTP真实文件解析已另验，浏览器上传保持未通过。
7. 额外教案DOCX/教材MD外发曾被自动审批拒绝：用户随后在本对话明确授权这两份材料及myai.bupt.edu.cn上游全链测试，获批后才执行。

8. 独立代码复核并新增回归：改纲成功后清除旧批准文件路径；保存绑定任务ID和编辑序号，切换前等待落盘；单页目标从HTTP硬传入内核意图校验；重试保留原操作和instruction。无kernel恢复完整初始化风格模板与源大纲。晋升前验证所有未改页的实际XML、像素和备注，标题页仅允许原标题对象文字体变化。
9. POTX兼容：python-pptx不直接接受模板内容类型；保留上传原字节和SHA，生成只更正主文档容器类型的PPTX源副本，所有母版、版式和资源字节保持。真实版式数来自已解析的所有母版关系。
10. 模型大纲refs偶发返回数组：严格校验字符串字段，模型重试只修JSON字段类型并保持稳定页ID、事实与素材，不由程序删减教学内容。
11. 无模板风格源没有images目录：固定原图staging显式创建目录，按输入SHA校验复制，恢复时同样核验；不使用替代图。
12. 模型生成SVG将源canvas四舍五入：错误消息直接提供精确viewBox并要求只返回内部canonical groups；未来风格源用精确EMU尺寸。不放宽边界与图片可读尺寸。
13. 图片清单诊断图误放stage目录：移入inventories子目录，避免模型调用归档stage.*时带走清单图。
14. 浏览器下载被拒绝：遵守工具返回的用户拒绝，不换浏览器或HTTP GET绕过。下载路由单元测试通过，实际浏览器下载未通过；HEAD仅验证元数据，不代表文件下载完成。
15. 独立审查发现慢上传跨任务串写：上传启动捕获taskEpoch，返回时若用户已切换任务就不更新当前表单；延迟上传测试同时覆盖参考资料和模板。
16. 人工逐页发现自动质检遗漏：上游v001第2页未写“均匀采样”，通过真实单页反馈建立v002修复，保留v001原证据。质量缓存现保留像素/合同不变页上的全部既有问题，避免只继承visual范围而丢弃content轻微问题。自动质检不是用户验收或人工核对的替代。
