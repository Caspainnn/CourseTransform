# 整体流水线与接口契约

这份文档解决三个问题：

1. 你们整条“教材 PPT → 教材 md → 教案 → PPT 课件”的链路怎么分工；
2. 你负责的第 2 段，输入输出到底是什么；
3. 上下游怎么接，才不会在联调时互相返工。

---

## 一、角色与交付物

| 环节 | 负责人 | 输入 | 输出 | 验收标准 |
| --- | --- | --- | --- | --- |
| ① 教材 PPT → 教材 md | 上游同学 | 教材 PPT / PDF / 原始教材 | 全本 `textbook.md` + 可选 `chapters.json` | 章/节层级清楚；一行对应一段可引用文本；行号稳定 |
| ② 教材 md + 教案模板 → 教案 | **你** | `textbook.md`、每章 `template.docx`、教学简报 | 每章 `教案.docx` + `教案.md` + `lesson_plan.json` + 质检报告 | 目标可测、时间对齐、引用可回查、模板字段填满 |
| ③ 教案 + PPT 模板 → PPT 课件 | 下游同学 | `lesson_plan.json`（推荐）或 `教案.md` | `.pptx` | 页序与教学环节一致；要点来自教案；不把整段文字搬上 slide |

关键原则：**相邻环节只通过文件契约耦合，不通过“口头约定 + 重新解析文档”耦合。**

---

## 二、端到端数据流

```text
┌──────────────┐     textbook.md      ┌──────────────────┐
│ 教材 PPT/PDF │ ───────────────────► │ 教案生成 Agent     │
└──────────────┘     chapters.json    │                  │
                                      │ 1. 切章/锚点      │
┌──────────────┐     template.docx    │ 2. 模板字段识别    │
│ 教师教案模板 │ ───────────────────► │ 3. 三阶段生成      │
└──────────────┘     brief.json       │ 4. 质检/修复       │
                                      │ 5. 套模板渲染      │
                                      └────────┬─────────┘
                                               │
                 ┌─────────────────────────────┼─────────────────────────────┐
                 ▼                             ▼                             ▼
          教案.docx                     教案.md                  lesson_plan.json
          （教师交付）                  （人读/兜底）              （机器契约）
                                                                         │
                                                                         ▼
                                                                  PPT 生成 Agent
```

### 为什么下游要读 JSON，而不是 DOCX

- DOCX 是“排版结果”，不是“数据”；从 DOCX 反解表格、合并单元格、标题层级非常脆弱。
- `lesson_plan.json` 把“第几课时、第几个环节、多少分钟、对应哪条目标、评价证据是什么”都结构化了，PPT 生成可以直接遍历。
- 教案 DOCX 里可能出现教师模板的固定文字、页眉页脚；JSON 里没有这些噪声。

如果下游暂时只能读文本，读 `教案.md`，不要读 DOCX。

## 三、上游契约：`textbook.md`

### 3.1 最低要求

- 一级标题 `#` = 章；二级 `##` = 节；
- 或者：每章以“第 X 章 ……”单独成行，每节以“第 X 节 ……”单独成行；
- 正文按自然段换行，不要把整章压成一行；
- 不要插入会随 PPT 页数变化的“第 3 页”“Slide 12”之类标记；
- 保留标点、数字、英文缩写，引用回查依赖这些字符。

### 3.2 推荐格式

```markdown
# 第一章 走进人工智能

（章导语）

## 1.1 什么是人工智能

（正文……）

## 1.2 从图灵测试到生成式人工智能

（正文……）
```

### 3.3 标题层级不可靠时：`chapters.json`

```json
{
  "title": "人工智能初步",
  "chapters": [
    {
      "id": "ch01",
      "title": "第一章 走进人工智能",
      "start_line": 1,
      "end_line": 120
    },
    {
      "id": "ch02",
      "title": "第二章 机器如何学习",
      "start_line": 121,
      "end_line": 260
    }
  ]
}
```

运行：

```powershell
python -m jiaoan run --textbook textbook.md --manifest chapters.json ...
```

行号从 1 开始，且包含首尾行。`manifest` 的优先级高于自动识别。

### 3.4 上游自检

```powershell
python -m jiaoan chapters --textbook textbook.md
```

检查：

- 章数对不对；
- 每章行号是否连续、有没有把目录/页眉当成章；
- 每章字数是否大致合理；
- 每章小节数是否与教材目录一致。

## 四、你的输入契约：教案模板

### 4.1 三种模板写法（可混用）

**A. 占位符（最推荐）**

```text
{{title}}
学科：{{subject}}  年级：{{grade}}  课时：{{duration}}  课型：{{lesson_type}}

一、教材分析
{{analysis}}

二、学情分析
{{student}}

三、教学目标
{{objectives}}

四、教学重点与难点
{{key_difficulties}}

六、教学过程
{{process}}
```

**B. 标准字段标题**

```text
一、教学目标
（正文）

二、学情分析
（正文）
```

识别到标题后，内容插在标题下方，直到下一个标题。

**C. 表格字段**

信息表：

| 课题 | {{title}} | 学科 | {{subject}} |
| --- | --- | --- | --- |
| 年级 | {{grade}} | 课时 | {{duration}} |

教学过程表：

| 教学环节 | 时间 | 教师活动 | 学生活动 | 设计意图 | 评价方式 |
| --- | --- | --- | --- | --- | --- |
| （示例行，会被删除） | | | | | |

### 4.2 字段命名

规范 key 与常见叫法（部分）：

| key | 模板里可以写 |
| --- | --- |
| `title` | 课题、教学内容、课程名称、课名 |
| `analysis` | 教材分析、内容分析、教学内容分析 |
| `student` | 学情分析、学习者分析、学生分析 |
| `objectives` | 教学目标、学习目标、核心素养目标 |
| `key_points` | 教学重点、重点 |
| `difficulties` | 教学难点、难点 |
| `key_difficulties` | 教学重点难点、重难点 |
| `methods` | 教学方法、教法学法、教学策略 |
| `materials` | 教学准备、教学资源、教具准备 |
| `process` | 教学过程、教学活动、教学环节、教学流程 |
| `board` | 板书设计、板书 |
| `homework` | 作业设计、作业布置、课后作业 |
| `assessment` | 教学评价、评价设计、目标达成 |
| `reflection` | 教学反思、课后反思 |

完整表见 `jiaoan/template.py` 的 `SLOT_ALIASES`。遇到新叫法，直接加一行 alias，不要改渲染逻辑。

### 4.3 每章模板不同

```text
templates/
├─ ch01.docx
├─ ch02.docx
├─ ch03.docx
└─ default.docx
```

```powershell
python -m jiaoan run ... --template templates\
```

选择顺序：

1. 文件名等于章节 id（`ch01.docx`）或章节标题；
2. 文件名包含章节 id/标题；
3. `default.docx` / `template.docx` / `模板.docx`；
4. 目录里只有一个文件时，用它。

### 4.4 先检查，再生成

```powershell
python -m jiaoan inspect-template --template templates\ch01.docx
```

重点看：

- `识别字段` 数量是否覆盖模板里的所有栏目；
- `教学过程表` 是否被识别，列映射是否正确；
- `警告` 里有没有“未识别的字段标题”。

未识别字段不会被自动填充，但会原样保留在 DOCX 里。

## 五、你的输出契约：`lesson_plan.json`

### 5.1 顶层结构

```json
{
  "schema_version": "1.0",
  "meta": {},
  "analysis": {},
  "objectives": [],
  "key_points": [],
  "difficulties": [],
  "methods": [],
  "materials": [],
  "lessons": [],
  "assessment_plan": [],
  "coverage": [],
  "board_design": {},
  "homework": [],
  "differentiation": {},
  "reflection": [],
  "citations": [],
  "ppt_brief": {},
  "custom_slots": {}
}
```

### 5.2 关键字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `meta.duration_minutes` | int | **单课时**时长，不是总时长 |
| `meta.periods` | int | 课时数；总时长 = duration × periods |
| `objectives[].id` | string | `O1`/`O2`…，全章唯一 |
| `objectives[].statement` | string | 用“能……”写可观察结果 |
| `objectives[].evidence` | string | 达成证据，和评价任务对应 |
| `lessons[].phases[].minutes` | int | 单课时内环节分钟数，合计必须等于 `duration_minutes` |
| `lessons[].phases[].objective_ids` | string[] | 该环节支撑哪些目标 |
| `lessons[].phases[].figure_ids` | string[] | 该环节的配图 id |
| `figures[].id` | string | `fig01`，与上传图片一一对应 |
| `figures[].path` | string | 相对输出目录的 `images/...` 路径 |
| `figures[].caption` | string | 8-30 字图注，DOCX 会显示 |
| `figures[].placement` | string | `phase` / `analysis` / `appendix` |
| `figures[].phase_id` | string | placement=phase 时必填 |
| `lessons[].phases[].assessment` | string | 该环节怎么判断达成 |
| `assessment_plan[]` | object[] | 每个目标一条：方式 + 证据 |
| `coverage[].section` | string | 必须与教材小节标题一致 |
| `citations[].quote` | string | 教材原文逐字摘录 |
| `citations[].source_lines` | [int,int] | 教材文件行号，闭区间 |
| `ppt_brief.slide_outline[]` | object[] | 下游 PPT 的页序骨架 |

### 5.3 下游 PPT 的推荐映射

```text
封面：meta.title + subject/grade
目标页：objectives[].statement
导入页：lessons[0].phases[0]
新知页：按 phases 的 name/teacher_activity 提炼
任务页：phases 中 name 含“任务/探究/实践”的环节
评价页：assessment_plan
总结页：board_design
作业页：homework
```

`ppt_brief.slide_outline` 已经给出了一版页序与要点，下游可以：

- 直接采用；
- 或只把它当参考，按 `lessons[].phases` 重新组织。

### 5.4 状态与失败语义

`run.json` / `manifest.json` 中每章状态：

| status | 含义 | 你该怎么处理 |
| --- | --- | --- |
| `ok` | 全部硬性检查通过 | 可直接进入人工复核 |
| `ok_with_warnings` | 通过，但有建议项/模板警告 | 看质检报告，决定是否改 Prompt |
| `quality_failed` | 自动修复后仍有硬错误，或 DOCX 验收未通过 | **不要直接交付**；看 `质检报告.md` / `验收报告.md`，返工重跑 |
| `failed` | API/模板/解析错误 | 看 `error` 字段；修复配置后重跑 |
| `dry_run` | 只生成了 Prompt | 用于调 Prompt，不是成品 |

每章输出新增：

- `模板说明书.md`：模板 word 的字段/表格说明（对应“模板 → AI 理解 → 说明书”）；
- `验收报告.md`：读取实际 DOCX 检查占位符、环节、配图嵌入、图注；
- `图片清单.json` + `images/`：上传配图、OCR、分配位置和 DOCX 实际使用的副本。

CLI 退出码：

- `0`：全部成功（含 warnings）；
- `1`：有 `failed`；
- `2`：配置/输入错误；
- `3`：有 `quality_failed`。

批量系统应根据退出码和 manifest 状态决定是否重试/告警。

## 六、联调顺序（建议照这个顺序做）

1. **只跑 `chapters`**：确认上游 md 的章节切分和行号。
2. **只跑 `inspect-template`**：确认教师模板字段，不改模板就先适配 alias。
3. **`--dry-run`**：看 Prompt 和教材上下文，确认没有把整章截没。
4. **`--offline`**：确认 DOCX 能打开、表格不炸、下游能读到 JSON。
5. **单章真模型**：`--chapters ch01 --no-review`，先控成本。
6. **人工改到可上课**：记录改动类型。
7. **加 `--review`**：看教研复核是否抓到有价值的问题。
8. **批量 5-10 章**：看失败率、token、耗时。
9. **接下游 PPT**：只传 `lesson_plan.json`，不要传 DOCX。
10. **做评测集**：20 章左右，固定教材/模板/模型，回归 Prompt 改动。

## 七、常见联调问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 只生成 1 章 | md 只有一个 `#` 或没有章节标记 | 用 `chapters.json` 指定行号 |
| 某章内容为空 | manifest 行号写错，或章节标题在范围外 | `chapters` 命令核对行号 |
| 模板字段大量空着 | 字段叫法不在 alias 表 | `inspect-template` 看未识别标题，补 alias 或改模板 |
| 教学过程表没填 | 表头不是“教师活动/学生活动”等标准叫法 | 改表头，或在 `PHASE_COLUMN_ALIASES` 加别名 |
| DOCX 表格列宽很怪 | 模板 tblGrid 列宽异常 | 在 Word 里把模板表格列宽调好，工具会按 2.4/1.2/4.6/4.1/2.8/1.9cm 重设教学过程表 |
| 引用全被丢弃 | 模型改写原文，回查失败 | 看质检报告；Prompt 已要求逐字引用，仍失败就换更强模型 |
| `quality_failed` 反复出现 | 模型不遵守时间/对齐约束 | 先 `--no-review` 降成本；把报告里的问题喂给模型做单点修复；必要时人工改 JSON 后重渲染 |
| 下游说 JSON 字段看不懂 | 没对齐 schema | 以本文第五节和 `lesson_plan.json` 示例为准，冻结 `schema_version` |

## 八、最小验收清单

- [ ] `chapters` 输出的章数、行号、节数与教材目录一致；
- [ ] `inspect-template` 识别出模板里所有需要填的栏目；
- [ ] 单章 DOCX 能打开，表格不跨页断裂，字段不为空；
- [ ] `lesson_plan.json` 能被下游脚本 `json.load` 并遍历出每课时环节；
- [ ] 每课时 `sum(phases.minutes) == meta.duration_minutes`；
- [ ] 每条目标在 `phases[].objective_ids` 和 `assessment_plan` 中都出现；
- [ ] `citations` 至少 2 条，且 quote 能在教材原文中搜到；
- [ ] 质检报告里没有“错误”，只有可解释的“建议”；
- [ ] 教师人工复核后，能直接拿 DOCX 上课。
