# 正式接入计划与审计

用户已授权直接实施全部交接范围，不再进行常规设计确认。视觉以 reference/workbench.html 为基准。

1. 隔离生产源码：复用原生内核和QC v4，独立7863端口、data存储；运行时显式配置，旧7862服务与实验只读。
2. 真实上游：文件内容验证、持久化知识库、DOC/DOCX/PDF/MD/TXT解析、模型大纲和编辑保存；扫描PDF明确报错。
3. 接通制作：任务队列、真实阶段、逐页PNG、稳定页ID反馈、版本、确认下载、失败恢复和冲突。
4. 技术验收：单元/HTTP/浏览器交互、新材料模型大纲及原7页重新制作、严格标题范围审计；整理发布文档与本地Git。

技术选择：Flask与原生JS，沿用原HTML/CSS，无前端构建依赖。持久化原子JSON，单制作线程，共享OS级PowerPoint锁。独立项目当前不需要多用户权限系统，仅监听127.0.0.1。

审计风险：PPT Master完整发行包不能随意重分发，采用外部显式路径；旧默认路径指向实验目录必须移除。PowerPoint仅Windows桌面可用。模型制作可能失败，必须保留候选并允许按失败页恢复。现有修改内核支持标题与合并，界面其他单页意图需扩展真实模型编辑而非词语猜测。

验收命令与实测结果持续写入 docs/技术验收.md。用户验收项保持待验收，自动通过单独记录。
